# Changelog

## 2026-11-18

`cutout_png` includes a `media` line on success when the chat can attach a file. When Hermes calls `transform_llm_output`, that hook adds a line to the reply for each PNG this turn wrote that the reply left out, other than a PNG written between two session changes in that turn. A fenced code block, a blockquote, or a JSON string is not treated as already written. Inline code is treated as already written when the whole text inside the backticks is a `MEDIA:` line and that path exists, because Hermes attaches it. A `/btw` answer and a background review do not receive the line. The turn reply does. With `compression.in_place: false`, one session change in a turn still puts the line on that reply. When the session changes twice in one turn, a PNG written between those two changes gets no line on the reply. That PNG stays in the folder you named. The default `in_place: true` keeps the line on that reply. When Hermes ends the turn with an empty final reply, it does not call `transform_llm_output`, so no line is added. The PNG stays in the folder you named. The next turn's reply does not gain the line. That empty final reply was checked on Hermes 0.22.2 and 0.23.1 when an empty body continued until the repeat limit. A `pre_llm_call` hook runs at the start of each turn and forgets a PNG an earlier turn did not deliver, so a later reply does not gain it. The line is `MEDIA:` plus the path of the PNG just written. On Telegram the line also has `[[as_document]]`, so the PNG is sent as a file. A photo send of a large image would fill transparent pixels with white. A terminal, SMS, ACP, and the local gateway still return the path and do not gain the line. An inherited `HERMES_SESSION_SOURCE` does not turn a terminal into Desktop. Desktop receives the line because that session binds the source. `api_server`, `webhook`, and `msgraph_webhook` are refused before a write, so nothing is written and no path is returned. The Hermes `api_server` chat, completions, and responses endpoints can inline a `MEDIA:` image as a data URL, and this plugin does not write on that surface. A failed call does not add the line. The PNG is still written only in the folder you named.
